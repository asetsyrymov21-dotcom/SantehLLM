# CLAUDE.md — Инструкция для агента

## Правило №1: Карта проекта — только когда нужно менять файл

**Не читай `project_map.md` просто так.** Карта нужна только в одном случае: ты собираешься найти, создать или отредактировать файл и не помнишь, где он лежит.

Если задача — объяснить, ответить на вопрос, проанализировать код уже открытого файла — карту не трогай.

### Когда читать карту

- ✅ Нужно найти файл для редактирования и путь не известен
- ✅ Нужно создать новый файл и надо понять, куда его положить
- ✅ Нужно разобраться, какой сервис/репозиторий отвечает за нужную логику

### Когда карту читать НЕ нужно

- ❌ Отвечаешь на вопрос по коду — просто отвечай
- ❌ Файл уже открыт / путь уже известен — иди сразу к нему
- ❌ Задача не требует изменений в файлах

### Алгоритм работы с кодом

```
1. Получил задачу → нужно ли менять файл?
   - Нет → работай без карты
   - Да, путь известен → иди сразу к файлу через Read
   - Да, путь не известен → прочитай project_map.md, найди файл, иди к нему
2. Точечно редактируй через Edit (не переписывай весь файл без необходимости)
3. Если создал новый файл → обнови project_map.md
```

### Что нельзя делать без причины

- ❌ `Glob("**/*.py")` по всему проекту — только если файл точно не найден в карте
- ❌ Читать `__pycache__`, `.pyc`, `.pytest_cache` — они не содержат логики
- ❌ Перезаписывать файл целиком, если нужно изменить 2-3 строки — используй Edit
- ❌ Открывать несколько файлов "на всякий случай" — сначала читай карту, потом конкретный файл

## Архитектура проекта

**Santeh Inventory** — система учёта сантехнических товаров.

Стек: **FastAPI** (REST API) + **aiogram** (Telegram-бот) + **PostgreSQL** + **OpenAI** (LLM + эмбеддинги).

```
app/
├── main.py              ← FastAPI app factory
├── core/                ← конфиг, логирование
├── api/                 ← HTTP-эндпоинты (роутеры)
├── bot/                 ← Telegram-бот (handlers, keyboards, FSM)
├── db/                  ← ORM-модели, сессии, миксины
├── repositories/        ← слой доступа к БД
├── services/            ← бизнес-логика
│   ├── pdf/             ← парсинг PDF-каталогов
│   ├── pdf_enrichment/  ← обогащение товаров из PDF
│   ├── product_import/  ← импорт товаров из Excel
│   ├── stock_import/    ← импорт остатков
│   └── request_check/   ← проверка запросов покупателей
├── rag/                 ← RAG-поиск по эмбеддингам
├── schemas/             ← Pydantic-схемы (request/response)
└── utils/               ← вспомогательные утилиты
```

## Ключевые файлы (часто нужны)

| Задача | Файл |
|--------|------|
| Изменить модель данных (поле в БД) | `app/db/models.py` + новая миграция в `alembic/versions/` |
| Добавить API-эндпоинт | `app/api/<область>.py` + зарегистрировать в `app/api/routes.py` |
| Изменить бизнес-логику | `app/services/<область>.py` |
| Изменить Telegram-хендлер | `app/bot/handlers/<хендлер>.py` |
| Изменить env-переменную | `app/core/config.py` + `.env.example` |
| Добавить схему запроса/ответа | `app/schemas/<область>.py` |
| Изменить логику парсинга PDF | `app/services/pdf/extractor.py` (или конкретный тип карточки) |
| Изменить импорт остатков | `app/services/stock_import/importer.py` или `matcher_v2.py` |
| Изменить импорт прайсов | `app/services/product_import/importer.py` |

## Соглашения

- **Репозитории** (`app/repositories/`) — только SQL-запросы, никакой логики
- **Сервисы** (`app/services/`) — вся бизнес-логика, используют репозитории
- **API** (`app/api/`) — только валидация входа/выхода, вызывают сервисы
- **Схемы** (`app/schemas/`) — Pydantic-модели для API
- Новые скрипты-утилиты → в `scripts/`
- Разовые фиксы данных → в `scripts/`, не в `app/`
